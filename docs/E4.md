# Conseils personnalisés par IA : synthèse

## 1. En résumé

Le projet est faisable : le prototype génère un bilan et 3 conseils au format JSON à partir des séances d'un utilisateur. Intégration estimée à 3 à 4 semaines, à condition de passer par un backend, d'utiliser le palier payant, de recueillir le consentement (RGPD) et de suivre la qualité des réponses.

## 2. Choix techniques

| Choix | Raison |
|---|---|
| Gemini au lieu de Mistral | Contrainte du projet, sortie JSON contrôlée par un schéma |
| Modèle Flash configurable | Bon rapport qualité/coût, un modèle a été retiré pendant les tests |
| Appels via le backend | La clé API reste secrète |
| Température 0 | À 1, le modèle a inventé des faits |
| Réflexion limitée, sortie plafonnée | La réflexion a représenté jusqu'à 66 % des tokens |
| Données pré-calculées et minimisées | Pas d'erreur de calcul, aucune donnée identifiante |
| Avertissement médical ajouté par l'application | Toujours présent et formulé correctement |

## 3. Raisonnement derrière les prompts

- Instructions et données séparées, pour faire évoluer l'un sans l'autre.
- Prompt en sections : contexte, tâche, ton, données, règles, format, exemple.
- Chaque règle corrige un défaut observé en test (vouvoiement, markdown, progression inventée, +17 % de distance).
- Un exemple de réponse fixe le style attendu.
- Les données pré-calculées font une grande partie du travail : le prompt apporte surtout la fidélité et la constance du ton.

## 4. Métriques

- **Automatiques** : taux de JSON valide, respect des règles (3 conseils, tutoiement, distance maximale), chiffres absents des données (inventions).
- **Humaines** : note mensuelle de 50 réponses par un coach (pertinence, clarté, utilité).
- **Utilisateurs** : retours « utile / pas utile », taux d'utilisation.
- **Techniques** : temps de réponse, taux d'erreur, taux de cache, coût par génération (`usageMetadata`).

## 5. Limites et risques

- Peu de tests : un profil, un cas limite, un essai par réglage.
- Réponses non déterministes, inventions réduites mais possibles.
- Cas limites fragiles : avec une séance, deux sorties de 1,7 km proposées et un vouvoiement.
- Conseils parfois vagues, ton identique quel que soit le niveau.
- Coût variable : de 545 à 1 496 tokens par appel.
- Dépendance à Google : modèles retirés, surcharges (503).
- Prototype testé dans Postman uniquement.

## 6. Éthique

- **Santé** : pas de diagnostic (vérifié en test), avertissement systématique, aucun conseil lié au poids.
- **Données** : la fréquence cardiaque peut être une donnée de santé. Consentement, information sur l'envoi à Google, désactivation possible.
- **Transparence** : conseils signalés comme générés par IA.
- **Confiance excessive** : ton suggestif, jamais injonctif.

## 7. Expérience utilisateur

- Génération au clic avec indicateur de chargement (quelques secondes d'attente).
- En cas d'erreur, derniers conseils disponibles ou message simple.
- Une carte par conseil, une couleur par priorité, mention « généré par IA ».
- Ton bienveillant, même quand l'objectif n'est pas atteint.

## 8. Implémentation

| Tâche | Durée |
|---|---|
| Endpoint backend (données, appel, validation) | 3 à 4 jours |
| Erreurs, cache, quotas | 2 jours |
| Interface | 2 à 3 jours |
| Tests de prompts sur une dizaine de profils | 3 jours |
| RGPD | 1 à 2 jours |
| Bêta et corrections | 1 semaine |
| **Total** | **3 à 4 semaines** |

## 9. Pistes d'amélioration

- **Prompt** : une action précise par conseil, interdiction explicite du vouvoiement, exemple plus court.
- **Données** : plancher de distance maximale (10 km), niveau de l'utilisateur calculé, objectif déclaré.
- **Technique** : cache du prompt système, streaming, comparaison avec d'autres modèles, évaluation automatique par un second modèle, A/B test des prompts.
- **Fonctionnalités** : plan d'entraînement hebdomadaire, conversation avec le coach.
